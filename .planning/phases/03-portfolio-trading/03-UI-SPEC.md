## Component Inventory

### 1. Header Additions (PORT-01, PORT-02, PORT-03)

The existing header in `page.tsx` must be extended with three new elements. The header `gridArea: 'header'` is already 48px tall with `padding: '0 16px'`, `gap: 24`.

**Portfolio value display (PORT-01)**
- Label: "PORTFOLIO" — 11px, weight 600, color `#8b949e`, letter-spacing 0.15em
- Value: live total_value from `GET /api/portfolio` — 13px, weight 600, color `#e6edf3`
- Updates: recalculates as SSE prices stream (position qty × current price + cash)
- Position: left of center in header, after wordmark
- Format: `$12,345.67` (USD, 2dp, comma-thousands)

**Cash balance display (PORT-02)**
- Label: "CASH" — 11px, weight 600, color `#8b949e`, letter-spacing 0.15em
- Value: cash_balance from portfolio API — 13px, weight 400, color `#e6edf3`
- Updates: after each trade execution
- Position: adjacent to portfolio value in header
- Format: `$10,000.00`

**Connection status dot (PORT-03)**
- A filled circle, 8px × 8px, `border-radius: 50%`
- Colors per state: connected `#22c55e`, reconnecting `#ecad0a`, disconnected `#ef4444`
- Tooltip on hover: "Connected" / "Reconnecting..." / "Disconnected" — 11px, color `#8b949e`
- Position: right-most element in header (after `marginLeft: 'auto'` spacer)
- The existing "LIVE" text placeholder at right of header should be replaced by this dot

### 2. Portfolio Section (gridArea: 'port')

The `port` grid area is currently a placeholder. Phase 3 replaces it with a tabbed/stacked layout containing four sub-panels.

**Layout within `port` area:**
The port section occupies the bottom-left cell of the CSS grid. It must fit without scroll at typical screen heights. Use a flex-column layout with:
- Sub-panel header tabs: 32px fixed height (matches watchlist panel header pattern)
- Content area: flex 1, overflow hidden internally per sub-panel

The port area must contain all four of: heatmap, P&L chart, positions table, trade bar. Recommended layout — two rows within the port cell:
- Row A (top half): Heatmap | P&L chart side by side (50% / 50% split)
- Row B (bottom half): Trade bar (32px fixed) + Positions table (flex 1) + Trade history collapsible

**Alternatively** the executor may choose tabs (HEATMAP / CHART / POSITIONS / HISTORY) at the top of the port section with a single visible panel at a time. Either is acceptable; the executor decides. The tab bar must use the standard panel header style: 32px tall, `background: #161b22`, `border-bottom: 1px solid #30363d`, tab labels in 11px/600/`#8b949e`.

### 3. Portfolio Heatmap — Treemap (PORT-04)

- Library: recharts `<Treemap>` component (already in package.json per PLAN.md)
- Each rectangle: one position
- Rectangle size: proportional to portfolio weight (position_value / total_portfolio_value)
- Rectangle color:
  - Profit (unrealized_pnl > 0): `#22c55e` at 60% opacity as fill; label in `#e6edf3`
  - Loss (unrealized_pnl < 0): `#ef4444` at 60% opacity as fill; label in `#e6edf3`
  - Breakeven (unrealized_pnl === 0): `#30363d` fill; label in `#8b949e`
- Rectangle label: ticker symbol, 11px, weight 600, centered
- Sub-label: P&L percent, 10px, weight 400, centered below ticker
- Empty state: If no positions, show centered text "No open positions" — 11px, color `#30363d`
- Border: `#0d1117` gap between rectangles (recharts treemap default gap)
- Background: `#0d1117`
- No legend, no axes

### 4. P&L Chart (PORT-05)

- Library: recharts `<LineChart>` (established library per PLAN.md)
- Data source: `GET /api/portfolio/history` — array of `{total_value, recorded_at}` snapshots
- X axis: time (recorded_at), no label, tick format: `HH:MM` — 10px, color `#8b949e`
- Y axis: total_value in USD, right-aligned ticks — 10px, color `#8b949e`, format `$N,NNN`
- Line: single line, color `#209dd7` (accent blue), stroke-width 1.5px, no dots
- Grid lines: horizontal only, color `#21262d`, stroke-dasharray `3 3`
- Background: `#0d1117`
- Tooltip: dark background `#161b22`, border `1px solid #30363d`, text `#e6edf3`, 11px — shows `$value` at hovered time
- Empty state: "No history yet" centered — 11px, color `#30363d`
- Polling: fetch on mount + after each trade; do NOT poll on every SSE event (backend snapshots every 10s)

## Interaction Contracts

### Trade execution flow
1. User fills ticker + qty in trade bar → clicks Buy or Sell
2. Button enters loading state ("...", disabled, opacity 0.6) — inputs disabled
3. `POST /api/portfolio/trade` called
4. On success:
   - Loading state clears
   - Positions table re-fetches (`GET /api/portfolio`)
   - Trade history re-fetches (`GET /api/trades`)
   - P&L chart re-fetches (`GET /api/portfolio/history`)
   - Header cash/total value updates from portfolio response
   - Ticker and qty inputs cleared
5. On error (4xx from API):
   - Loading state clears
   - Error message appears below trade bar (11px, `#ef4444`)
   - "Insufficient funds" if 402/400 with funds message; "Insufficient shares" if 400 with shares message; otherwise the API error message verbatim
   - Auto-dismiss after 3 seconds

### Portfolio live recalculation (PORT-01)
- On each SSE `price_update` event, if the user has a position in that ticker, recalculate total portfolio value client-side: `sum(position.quantity × current_price) + cash_balance`
- Do NOT poll `GET /api/portfolio` for live value — use SSE prices + cached position data
- Fetch full portfolio on: mount, after trade execution

### Heatmap update trigger
- Heatmap re-renders whenever: positions data changes (post-trade) OR SSE prices update (for color/size recalculation)
- Color and size update on every SSE price event for held tickers
